# 依机位剪片

**适用前提：整支影片有一个「主机位」，占掉大半时长，而且机位固定。** 球场后方的定机、讲台正面的定机、会议室的固定摄影机都算。手持跟拍、频繁推轨变焦的片子不适用——那种片子每一帧长相都不同，这套方法会整片误判。

不适用时直接讲，别硬做。

核心手法：把整片降采样成小图，取中位数当「主机位的平均长相」，每帧对它算 L1 距离。主机位的帧距离小、特写／观众／转场卡距离大，两群分得很开。

## 流程

### 0. 确认工具

需要 `ffmpeg`／`ffprobe`（`brew install ffmpeg`）与 `numpy`。两支脚本都吃 `FFMPEG`／`FFPROBE` 环境变数，PATH 里没有时用它指路。

### 1. 先用眼睛看一遍镜头结构

**不要跳过这步。** 你得先知道「主机位」长什么样、有哪几种杂镜头，后面的数字才有意义。

```
python3 scripts/detect.py VIDEO --contact-sheet /tmp/sheets
```

出一叠缩图墙，每格 2 秒。读完再往下。**顺便确认前提成立**——如果缩图墙上根本没有一个压倒性的主机位，回到上面那句「不适用时直接讲」。

### 2. 逐帧侦测

```
python3 scripts/detect.py VIDEO --json plan.json --min-seg 3
```

- **取样率一定要用原生 fps**（预设就是）。用 10fps 之类的粗取样，边界会有 ±0.1 秒误差，剪完接点上会挂着几帧杂镜头。
- `--min-seg` 是「短于这个秒数的保留段直接丢掉」。夹在两段杂镜头中间的两三秒主机位孤岛，留着反而突兀，预设 1 秒通常要往上调到 3。
- 阈值自动算（Otsu 与 MAD 取较小者）。结果不对时用 `--threshold` 手动指定，判断依据是那行印出来的距离分布：主机位落在 p50 附近，杂镜头在 p90 附近，阈值抓中间。

把印出来的保留／剪掉清单**拿给用户看过再剪**。他要的「杂镜头」定义可能跟你猜的不一样。

### 3. 剪

```
python3 scripts/cut.py VIDEO --plan plan.json -o out.mp4 --mode hybrid --verify
```

| 模式 | 画质 | 切点 | 什么时候用 |
|---|---|---|---|
| `hybrid`（预设） | 九成以上原始位元流 | 精准 | 绝大多数情况 |
| `lossless` | 完全无损 | 精准，但**段首会牺牲画面** | 用户明讲要 `-c copy` |
| `reencode` | 全片重压 | 精准，时间戳最干净 | 成片还要进后制流程 |

`lossless` 的代价要讲清楚：每段起点只能落在关键帧上，对不齐时整个段首都得往后让。今天那支球赛片就少掉 13 秒好画面（264.7s → 251.6s）。`hybrid` 就是拿来解这件事的——只把「段首到下一个关键帧」那一小截重压，其余照抄，实测重编码占比不到 5%。

**`--verify` 一定要开。** 它在成片上重跑一次侦测，逐帧回报还有没有漏掉的杂镜头。报出问题时依序试：

1. `--tol-frames 0`：不准为了迁就关键帧往前吃帧，改用桥接重压。
2. 还有的话，把它报的帧号抽出来目视确认（下面有指令）——也可能只是误判。
3. 真的漏了就 `detect.py --erode 2` 重新侦测。

### 4. 交付前抽帧目视

数字过了不等于对。把每个接点前后各抽一帧看过：

```
ffmpeg -i out.mp4 -vf "select=eq(n\,FRAME),scale=280:-1,format=yuvj420p" -frames:v 1 f.jpg -y
```

接点的帧号 = 前面各段帧数的累加，`ffprobe -select_streams v:0 -count_frames -show_entries stream=nb_read_frames` 一段一段数。

## 交付时要讲的话

- **成片长度与原片长度**，剪掉哪几段、各是什么内容（列表格）。
- **重编码占比**。宣称「无损」就要真的是 `-c copy`，混合模式要老实说重压了几秒。
- **已知瑕疵**。`hybrid`／`lossless` 走 concat 出来的档案，接点上会有重复时间戳（`non monotonically increasing dts`）。播放器都正常播，但用户之后拿去重新编码会看到警告；根除只能走 `reencode`。这件事要主动讲。
- 原始档不要动，成片另存新档名。

其余的坑——`-c copy` 的 `-to` 是封包层级、关键帧对齐、为什么阈值不能只用 Otsu——写在 [references/gotchas.md](references/gotchas.md)。**改脚本之前先读它**，那些行为都是踩过才知道的。
