# 技能树生成

**交付物是一份单档 HTML，发布成 Artifact。** 中间产物（`tree_data.py`、`build.py`、`skill-tree.json`）一律留在 scratchpad，除非用户明说要维护档。

生产流程：

```
scratchpad/
├── tree_data.py          ⭐ 资料单一来源（你写这个）
├── build.py              产生器 + 验证器（从 assets/ 复制）
├── index.template.html   UI 样板（从 assets/ 复制）
└── <slug>.html           产出 → 这个才是交给用户的东西
```

`python3 build.py` 会验证资料、把 JSON 灌进样板、吐出一份无外部依赖的单档 HTML。**验证不过 exit 1，别绕过去手改产物。**

> **输出语言一律繁體中文。** skill 文件本身是简体，但产出给用户的每一个字——节点标题、`desc`、`why`、任务、`dod`、题干、选项、解释、深挖 prompt——都用繁體。用户另有指定才改。

顺序是硬性的：**定位 → 摸底 → 调研 → 排依赖 → 写任务 → 出题 → build → 闸门。**

最常见的失败：跳过摸底直接生成一棵「通用路线图」。那种东西网上一搜就有，用户要的是**对着他现有能力标出缺口的那棵树**。

## Step 0 · 定位（不问会做错的三件事）

| 项目 | 为什么非问不可 |
|---|---|
| **目标身份** | engineer / TPM / researcher 决定同一棵树上哪些枝是主干哪些是装饰 |
| **产出目的** | 面试用 / 真的要做出东西 / 纯理解。决定 `dod` 写成「能讲清楚」还是「跑通并有数字」 |
| **硬约束** | 每週时数、总期限、现有硬体与预算。`weekly_hours` 直接决定 HUD 上的週数估计 |
| **既有素材** | 手上有没有课纲、笔记、repo、旧简报、书单。**一定要开口要**——用户自己的材料比你抓来的准，而且抓不到的内部脉络只有他有。没有就说没有，别默认他没有 |

用 AskUserQuestion 一次问完（四题上限刚好），**不要一题一题挤牙膏**。用户开场白讲过的不要再问。

素材如果是档案，先读完再进 Step 2——已经有的东西不要再上网抓一次。

## Step 1 · 摸底：反向问，不要正向问

不要问「你会不会 X」——用户对自己的估计不准。改成**让他判断一句具体陈述的对错**：

> ❌「你熟悉 ROS 2 吗？」
> ✅「ROS 2 的 DDS 让节点发现去中心化，所以不需要 roscore——这句对吗？」

一次给 8–12 条，覆盖各章，让用户勾「懂／模糊／没听过」。**刻意埋一条错误陈述**——能不能抓到它，比十条自评有用。

结果映射成初始状态：勾「懂」的节点在 `tree_data.py` 里预先勾好对应 tasks，其余留空。

**不做摸底就不要出树。**

## Step 2 · 调研

用 WebSearch / WebFetch 抓真实素材：

- 课程类：抓 syllabus、reading list、lab 列表，节点直接对应真实的 lecture / assignment。
- 领域类：抓官方 docs、benchmark、招聘 JD（JD 的要求栏就是现成的 `dod`）、社群公认的入门专案。
- 硬体相关：抓型号、价格、生态相容性，写进 `desc`。

资源连结要标 `k`（类型）与 `h`（时数），用户才能排预算。

**不要凭目录惯例推 URL**（`slides/01-intro.pdf` 这种猜法一半会 404）——去抓页面上真正的 href。交付前每条连结实际打一次确认回 200。

## Step 3 · 排依赖：树的骨架

节点完整规格见 `references/data-model.md`。硬规则：

- **前置链必须真的是前置**。「学 A 之前最好懂 B」不算，要「不懂 B 根本做不出 A」才算。
- **8–12 章（act），每章 4–8 节点**，总数 40–70。超过 70 切成两棵。
- **每章至少一个 `keystone`（◆ 枢纽）**——通过它之后，后面的做法会改变。这是菱形节点存在的理由，不是随便挑一个大的。
- **必须有跨章依赖**，否则那是几根平行棍子。build.py 会警告。
- **支线用 `track:"side"`**（虚线边框），不挡主线解锁。

座标是手写的。惯例（照 x 向右、y 向下）：

| | 惯例 |
|---|---|
| 主干 | x ≈ 1200 为中轴，同章节点在 ±200 内散开 |
| 支线 | 甩到 x ≈ 600–900（左）或 1700–1950（右），跟主干拉开 |
| 章带 | y 每章推进 150–400；章与章之间留 100–150 空隙给章节标题 |
| 同章 | 节点 y 间距 90–180，太挤标签会重叠 |

前置画在子节点上方（y 较小）。build.py 会警告逆流的边。

## Step 4 · 任务清单与验收条件

这是这套树最花工、也最值钱的部分。每个节点四个栏位：

- **`desc`** — 这是什么。写具体，不要抽象名词堆叠。
- **`why`** — 为什么值得花这几小时。这是动机，写成一句会被记住的话：「90% 的『我的机器人接上去没反应』都是权限问题。现在花 3 小时，之后省 30 小时。」
- **`tasks`** — 3–8 条**可勾选的具体动作**，每条都有可验证的产物。这是进度的唯一来源。
- **`dod`** — 一句可判定的验收条件。

`tasks` 与 `dod` 的分工：tasks 是过程，dod 是结果。

| ❌ | ✅ |
|---|---|
| 理解 IK 的原理 | 给定 6-DoF 手臂与目标位姿，手算雅可比并说明奇异点在哪 |
| 熟悉 Isaac Sim | 跑通一次抓取并把 policy 导到实体手臂，成功率 > 50% |

对应 Step 0 的产出目的：面试导向 → `dod` 偏「白板上能讲清楚」；实作导向 → 偏「跑通并有数字」。

## Step 5 · 出题

规格见 `references/questions.md`。摘要：

- **每节点至少 3 题**，全树 60–150 题。题少了这个专案就退化成一张海报。
- **四选一单选**，不要是非题——猜中率 50%，测不出东西。
- 每题必须有 **`ex`**（为什么对／其他三个各错在哪）与 **`dig`**（贴回 Claude 的深挖 prompt）。
- 写完**一定要跑 build.py**——定性原则挡不住反模式，尤其「正解永远最长」这条，第一版几乎必然全中。build.py 会直接挡下来。

## Step 6 · Build

把 `assets/build.py` 与 `assets/index.template.html` 复制进 **scratchpad**，写好 `tree_data.py`，然后：

```bash
python3 build.py
```

产出 `<slug>.html`——单一自足、无外部依赖、`<title>` 在最前面，可以直接丢给 Artifact 发布。

UI 的调整（配色、章节色、等级称号、闸门开关、深挖 prompt 措辞）走 `META`，**不要改样板**。样板契约见 `references/ui.md`。

## Step 7 · 闸门

`build.py` 会自动挡下大部分。**它 exit 1 就是没过，不要绕过去手改 index.html。**

自动检查：重复 id、不存在的前置、依赖循环、空任务、缺 desc/why/dod、dod 不可判定、题目挂错节点、非四选一、答案越界、缺 explain/dig、偷懒选项、解释自打脸、每节点题数、**答案位置分布**、**长度泄漏**、**dig 重复**。

自动警告（不挡，但要看）：跨章依赖过少、章内没有 keystone、任务数超出 3–8、节点没有资源、题数低于 60、前置视觉逆流。

**只有人能判断的，自己确认**：

- [ ] 树是对着**摸底结果**标的，不是通用路线图
- [ ] 每条 `deps` 都通过「不懂就做不出」测试
- [ ] keystone 真的是枢纽——过了它之后做法会变
- [ ] `why` 是会被记住的一句话，不是补充说明
- [ ] 外部连结**实际打过**回 200
- [ ] 座标不重叠，缩到全览时标签读得出来
- [ ] **全篇繁體**，没有混进简体字
- [ ] 产出档没有 `<!DOCTYPE>` / `<html>` / `<head>` / `<body>`（Artifact 会自己包）

## 交付

用 Artifact 发布 `<slug>.html`，把链接给用户。发布前先按 Artifact 的说明载入 `artifact-design`。

- **不要**把 `tree_data.py` / `build.py` / `skill-tree.json` 塞给用户——那是中间产物。用户开口要维护档时才给。
- 页面内建「說明」与「進度」两个对话框，所以不需要额外的 README。
- 提醒用户：进度存在浏览器 localStorage，**定期按「進度」把那段 JSON 复制存一份**；换浏览器或清快取后贴回去按「載入」还原。
- 答错的题不必整棵树重来：试炼区的「重置作答」只清**目前筛选范围**内的作答（选了某章就只清该章），任务勾选不受影响。规格见 `references/ui.md`。
- 顺带提醒：技能树会过时——课纲换届、论文换代、硬体换代时值得重跑一次这个 skill 更新分支。
