# 题库规格

题目放在 `tree_data.py` 的 `Q`，挂在节点上。

```python
{
 "n": "A1-3",              # 挂在哪个节点（要对得上 N 里的 id）
 "ty": "concept",          # concept | debug | tradeoff | numeric | scenario
 "q": "DDS 讓 ROS 2 不需要 roscore，主要是因為？",
 "o": ["...", "...", "...", "..."],
 "a": 2,                   # 0-indexed 正解
 "ex": "正解的機制是…。A 錯在…。B 混淆了…。D 在…情況下才成立。",
 "dig": {"s": "...", "m": "...", "t": "...", "p": "..."},
}
```

## 五种题型（一个节点的题要跨型，别三题都是 concept）

| 型 | 问什么 | 例 |
|---|---|---|
| **concept** | 机制为什么这样运作 | 「DDS 让 ROS 2 不需要 roscore，主要因为？」 |
| **debug** | 给症状，问最可能的原因 | 「topic 有资料但 rviz 不显示，最可能是？」 |
| **tradeoff** | 两个方案选一个并知道代价 | 「实时回路放 Jetson vs 放 MCU，主要代价是？」 |
| **numeric** | 数量级感 | 「谐波减速器的典型背隙落在哪个量级？」 |
| **scenario** | 放进真实决策 | 「预算 3 万要做 sim2real demo，先买哪个？」 |

**tradeoff 与 scenario 是拉开差距的题型。** 只出 concept 题的题库跟单字卡没两样。

## 干扰项怎么写

四个选项必须**长度相近、同一层级**。常见破功：

- ❌ 正解特别长、特别完整 —— 一眼就中（**最常犯，见下面的机械检查**）
- ❌ 干扰项明显荒谬 —— 变成三选一
- ❌ 出现「以上皆是」「以上皆非」 —— 偷懒，build.py 会挡

好的干扰项来自**真实的误解**：常见的混淆概念、上一代技术的答案、听起来合理但差一个前提的说法。写的时候问自己：「有没有人真的这样以为过？」没有就换一个。

## ex 怎么写

三句以内，结构固定：

> 正解成立的机制是 ___。A 错在 ___（那是 ___ 的行为）。B 混淆了 ___ 与 ___。D 在 ___ 情况下才成立。

**不要只解释正解。** 用户答错时想知道的是「我那个想法错在哪」。

## dig 怎么写（最重要）

用户答错或没把握时，一键复制、开新对话、把这个知识点挖到懂。样板会用 `META.dig_intro` / `dig_level` 加上这四个栏位组成完整 prompt：

| 栏位 | 内容 |
|---|---|
| `s` | 卡住的知识点，写具体 |
| `m` | 我原本以为——**取自该题最强的干扰项** |
| `t` | 但正确的是 |
| `p` | 这一题专属的追问。涉及实作的写「给我一段可以直接跑的最小 repro」 |

组出来长这样：

```
我正在學 <领域>，目前程度：<自述>。

我卡在這個知識點：{s}
我原本以為：{m}
但正確的是：{t}

請：
1. 用一個具體例子講清楚這兩者的差別，例子要有數字或可執行的程式碼
2. 指出我這個誤解在什麼情況下會真的害我做錯判斷，給一個實際會遇到的場景
3. {p}
4. 最後出 2 題選擇題追問我，確認我真的搞懂了——先別給答案
```

规则：

- **每题的 `m` 与 `p` 都要不一样**，把该题的误解写进去。同一段复制 80 遍等于没写，build.py 会挡。
- 结尾的「出题追问」是固定的——让深挖对话自己收敛，而不是散成一篇讲义。

## 机械检查：build.py 会挡，别靠肉眼

定性原则挡不住反模式，第一版几乎必然全中。`build.py` 会量这四个数，不过就 exit 1：

| 指标 | 怎么算 | 门槛 |
|---|---|---|
| **答案位置分布** | 正解落在 A/B/C/D 的次数 | 极差 ≤ max(2, 题数×5%)；出现 0 就是坏掉 |
| **长度泄漏** | 每题 `len(正解) / len(最长干扰项)` | 中位数 ≤1.10，且没有任何一题 >1.30 |
| **解释自打脸** | 正解字母是否出现在 `X 错／X 混淆／X 反了` 句式 | 必须 0 |
| **dig 重复** | 四个栏位串起来去重 | 去重后 == 题数 |

长度那条最容易失守：正解要承载完整机制所以天生较长，**未经检查的题库通常 90% 以上的正解都是最长选项**——那等于受测者不必懂任何东西，选最长的就能拿高分，整个题库失效。

修法两种，通常要合用：

- **把正解压短**：删掉括号补述与修饰语，只留机制本身。
- **把干扰项补到同等具体**：给它一个一样长、一样有术语密度的*错误*机制。顺带好处是干扰项变强了。

正解含长识别字（`OptimizeGroup`、`RelMetadataQuery`）时，干扰项也要放进同量级的识别字，否则长度差距补不平。

调整位置分布时**不要盲目 shuffle**：`ex` 里的「B 错在…」会跟着错位。用对调（正解与目标位置互换）并同步交换 `ex` 里那两个字母，只动两个位置、影响可控。注意别误伤指章节的写法（「这正是第三章那张图」）。

## 分布

- 低 tier 题多（打基础），高 tier 题精（每节点 3 题够）。
- `quiz_gate` 开着时，题库直接参与节点点亮——**这是让人真的去做题的唯一方法**。
