# 出题规格

对话式出题，一次一题。这份是四轮题目的写法、干扰项的写法、指针的写法、深挖 prompt 的格式。

## 五种题型

一场检核里的四题**必须跨型**。四题都是 concept 就是一叠单字卡。

| 型 | 问什么 | 例 |
|---|---|---|
| **concept** | 机制为什么这样运作 | 「動態平衡能維持住，主要是靠什麼？」 |
| **debug** | 给症状，问最可能的原因 | 「這個系統參數沒變卻開始漂移，最可能是哪個前提破了？」 |
| **tradeoff** | 两个方案选一个，并知道代价 | 「用負回饋壓住震盪，代價是什麼？」 |
| **numeric** | 数量级感 | 「人體體溫的調節誤差帶大約落在哪個量級？」 |
| **scenario** | 放进一个没讲过的真实场景 | 「你要判斷一間公司的庫存週轉算不算動態平衡，先看哪個數？」 |

对应四轮：轮 1 concept，轮 2 debug 或反例，轮 3 scenario，轮 4 tradeoff 或 numeric。

## 干扰项怎么写

题目出成 `AskUserQuestion` 选单时，**干扰项的战场在 `label`**——有些客户端只显示 label，
所以四个 label 必须各自独立读得懂、字数相近（6–14 字）、同一层级；`description` 是补机制的，不是补语意的。

四个选项必须**长度相近、同一层级**。常见破功：

- ❌ **正解特别长、特别完整**——一眼就中。**出题前实际数字数**，正解不能是最长的那个。
- ❌ 干扰项明显荒谬——变成三选一。
- ❌ 「以上皆是」「以上皆非」——偷懒。
- ❌ 题干里泄漏答案（把关键机制词写进题干，正解就是那个词）。

好的干扰项来自**真实的误解**：常见的混淆概念、上一代技术／旧理论的答案、听起来合理但差一个前提的说法。写的时候问自己：「有没有人真的这样以为过？」没有就换一个。

**最强的那个干扰项是这题的价值所在。** 如果四个选项里有三个是凑数的，这题只验证到「他有没有在读」。

## 难度怎么升

同一个概念，四轮换的是**要求的动作**，不是换更冷僻的名词：

| 轮 | 要求的动作 | 反例（做错的样子） |
|---|---|---|
| 1 辨识 | 从相邻概念里挑出它 | 问一个更生僻的同义词 |
| 2 边界 | 指出前提破掉时会怎样 | 问定义的另一种说法 |
| 3 迁移 | 在**解释里没出现过**的场景认出同一个机制 | 换个数字重问轮 1 |
| 4 取舍／量级 | 说出代价，或抓对数量级 | 问一个要死背的常数 |

第 1、2 轮全对而且答得很快 → **直接跳过一轮同级题，把 3、4 轮再拉高**（例如轮 4 改成两个都对但代价不同的选项）。第 1 轮就错 → 不要急着往下，先把边界补扎实。

## 指针怎么写

答错时给的第一段回应。**针对他选的那一个选项**，三个要素：

1. 他那个选项**在什么情况下会是对的**（承认它的合理来源，他才知道自己的直觉从哪来）
2. 这一题里**哪个条件**让它不成立
3. 一句「再想一次？」——**不给正解**

> 「你選的 B——在系統沒有外部輸入的時候，那確實就是最後的結果。但題目裡這個系統一直有能量進來，所以它停不在那裡。再想一次？」

不要写成完整讲解，那等于公布答案。指针的长度**不超过三句**。

## 深挖 prompt（结算时给）

给使用者一段可以直接复制、开新对话继续挖的 prompt。填四个栏位：

```
我正在搞懂 <概念>。

我卡在這個點：<具體的知識點，不是概念名稱>
我原本以為：<取自他實際選錯的那個選項>
但正確的是：<正解的機制>

請：
1. 用一個具體例子講清楚這兩者的差別，例子要有數字或可執行的東西
2. 指出我這個誤解在什麼情況下會真的害我做錯判斷，給一個實際會遇到的場景
3. <這一題專屬的追問>
4. 最後出 2 題選擇題追問我，確認我真的搞懂了——先別給答案
```

「我原本以为」一定要填**他真的选错的那个选项**，不要填一个泛用的误解。这是这段 prompt 唯一比通用提问强的地方。

四轮全对时，改给**往上一层**的 prompt：这个概念的上位框架是什么、它在哪个更大的体系里是一个特例。
