# 概念检核

使用者丢一个词或一组关系进来，交付物**不是一篇解释**，是一段有输赢的对话：讲完之后**至少四轮**四选一，把他从「看懂了」推到「真的懂」。

```
定深度 → 解释（短）→ 检核循环（≥4 轮，一次一题）→ 结算
```

> **输出语言一律繁體中文。** skill 文件本身是简体，但给使用者的每一个字——解释、题干、选项、指针、结算——都用繁體。使用者另有指定才改。

## 这个 skill 唯一的失败模式

**写一篇很好的解释，然后草草出两题、还自己把答案接在后面。**

那是把 concept-check 退化成一次普通问答。教学发生在检核循环里，不是在解释那一段——解释只是给他弹药，四轮题目才是把误解逼出来的地方。所以：

- 解释**默认 300–500 字**，不写讲义。他要深再展开。
- 出完一题就**停住等回答**。同一则讯息里出题又解答，等于什么都没验证到。

## Step 0 · 定深度（不要拷问）

使用者丢一个词进来是要答案，不是要面谈。**不准在解释前反问一串「你想学到什么程度」。**

三件事自己判断，判断不了就在解释里标注，不要卡住：

| 情况 | 做法 |
|---|---|
| **跨领域歧义**（「动态平衡」在生理学／机械／经济学都有） | 选最可能的那个直接讲，开头一句标注「我按 ___ 讲，你要的若是 ___ 说一声」 |
| **对方程度未知** | 从他的用词判断。讲得出专有名词就别从零讲起；第 1 题答对得太轻松，后面直接拉难度 |
| **需要真实资料**（版本、数字、规格、谁提出的） | 用 WebSearch／WebFetch 去查，**别凭印象讲**。这个 skill 的整个价值建立在讲的是对的 |

对话里已经讲过的脉络不要再问一次。

## Step 1 · 解释（四块固定结构）

四种问法的骨架不同——单一术语、两者关系、一整套体系、机制型「为什么会 X」——完整写法见 [`references/explain-shapes.md`](references/explain-shapes.md)。共通的四块：

1. **一句话定义**：先给准确的，不带比喻。比喻放第 4 块。
2. **机制**：靠什么撑住、为什么会这样运作。这一块是重点，不是名词罗列。
3. **边界**：什么**不是**它、什么时候它**不成立**。← **后面出题的弹药库，最容易考的都在这里。这一块缺席，四轮题只能全出定义题。**
4. **一个具体例子**：带数字、可执行、或一个真实场景。抽象讲完两句内必须落地。

## Step 2 · 检核循环（这个 skill 存在的理由）

出题与干扰项的完整规格见 [`references/question-design.md`](references/question-design.md)。硬规则四条：

- **一次一题，出完就停。** 不准一次丢四题（那样没有难度自适应，也没有指针机制）；不准自问自答。
- **至少四轮。** 答错的那轮**不算数**——补一题同知识点的变形题，答对才往下走。
- **用 `AskUserQuestion` 把题目出成 UI 选单**（一次 call 只放**一个** question）。栏位对应见下。
- **正解不准是最长的那个选项。** 出题前自己数一次字数——这是最常犯也最致命的破功，受测者不必懂任何东西，选最长的就能过。

### 题目怎么塞进 AskUserQuestion

四选一正好对上它「每题 2–4 个 option」的上限。栏位这样对：

| 栏位 | 放什么 | 注意 |
|---|---|---|
| `header` | `第 N 輪 · 辨識／邊界／遷移／取捨` | 上限 12 字元，别写题目 |
| `question` | 完整题干（情境＋问句） | 长度不受限，具体的场景写在这里 |
| `options[].label` | 选项主干，**6–14 字，四个字数相近** | **有些客户端只显示 label**——label 必须自己读得懂，不能靠 description 补完 |
| `options[].description` | 该选项的机制说明，一句 | 干扰项的说服力发力处；不准写成「这是对的／这是错的」 |
| `multiSelect` | 一律 `false` | |

配套的三条硬规则：

- **一次 call 只放一个 question。** 工具允许一次问四题，但那会一次丢四题给他，难度自适应与指针机制同时失效。
- **正解的位置要轮动。** 四轮不要都放第 1 个。也**不准**在 label 后面加「(Recommended)」——那是决策用法，用在题目上等于直接给答案。
- **补题也走同一套。** 答错后的变形题一样出成选单，`header` 沿用该轮编号。

使用者的回应对应处理：

| 回应 | 处理 |
|---|---|
| 选了某个 option | 照 Step 3 判对错 |
| 选 **Other** 打字（「不知道」「B 但不确定」） | 依 Step 3 的表处理；讲了理由就连理由一起检查 |
| 按 **Skip** | 记进结算的「没验到」，不要默默算他会 |

**降级**：环境没有 `AskUserQuestion`（纯文字 CLI、web、或工具被停用）时，退回文字格式——四个选项标 A/B/C/D，题干后附一行 `（回 A/B/C/D 就好；沒把握就說沒把握）`。选项过长塞不进 label 的题（例如要贴一段程式码）也走这条。

四轮是一道难度阶梯，不是四题同级的题：

| 轮 | 考什么 | 题型 | 通过代表 |
|---|---|---|---|
| 1 | **辨识**——能不能跟最近的邻居概念分开 | concept | 知道这个词 |
| 2 | **边界**——什么情况下它不成立 | debug／反例 | 不是背定义 |
| 3 | **迁移**——换一个没讲过的场景还认不认得出来 | scenario | 会用 |
| 4 | **取舍／量级**——知道代价，或有数量级感 | tradeoff／numeric | 真的懂 |

**第 3、4 轮才是拉开差距的地方。** 四轮都出 concept 题，跟单字卡没两样。

## Step 3 · 答错怎么办（指针机制）

答错时**不要马上公布答案**。两段式：

**第一次答错 → 只给指针，让他重选同一题。**

指针要**针对他选的那个选项**，不是泛泛提示：

> ✅「你选的 B 在 ___ 的情况下确实成立，但题目里的 ___ 让那条路走不通。再想一次？」
> ❌「不对喔，再想想看。」（没有资讯量）
> ❌「很接近了！」（他不知道差在哪，还以为自己方向对）

**同一题第二次还错 → 公布答案 + 完整机制**，明讲他那条思路错在哪一步，然后**补一题变形题**（换场景、换数字，考同一个机制），答对才进下一轮。

其他情况：

| 使用者的反应 | 处理 |
|---|---|
| 「不知道／没把握」 | 当**第一次答错**处理：给指针、让他再试。**不要直接公布答案**——硬猜跟真的懂是两件事，指针能把它们分开 |
| 答对但**理由是错的**（他有附解释） | 一样要纠正。答对不等于路径对，这种是最危险的假懂 |
| 「跳过这题」 | 跳，但记进结算的「没验到」栏，不要默默算他会 |
| 「不玩了」 | 立刻停。结算照给，明写哪些确认过、哪些没验到 |

## Step 4 · 结算（不准通篇肯定）

四轮走完（含补题）给一段短的：

- **已确认懂**：列**具体的机制**，不是「你懂了动态平衡」。写成「你能把 X 跟 Y 分开、也知道 Z 条件下它会失效」。
- **还薄弱**：哪一题错、错在哪个机制。全对就写「四轮都过，可以往下一层」。
- **一段可复制的深挖 prompt**：格式见 `references/question-design.md` 的「深挖 prompt」。薄弱点用它开新对话继续挖；全对的话，给的是「这个概念往上一层是什么」的 prompt。

## 禁止清单

| ❌ | 为什么 |
|---|---|
| 出完题接着自己解答 | 什么都没验证到，退化成普通问答 |
| 一次丢四题 | 没有难度自适应，也没有指针机制 |
| 解释写两千字讲义，然后出两题 | 顺序搞反了。教学在检核循环里发生 |
| 四轮都考定义 | 单字卡。第 3、4 轮才拉得开差距 |
| 答错马上公布答案 | 跳过指针 = 跳过这个 skill 最有价值的一步 |
| 正解明显最长最完整 | 选最长的就能过，整轮检核失效 |
| 「很接近了！」「不错喔」 | 他会误以为自己方向对。**这个 skill 的价值就是别让他带着错觉离开** |
| 结算写「你完全掌握了」 | 没验到的部分要明写没验到 |
| 一次 `AskUserQuestion` 塞四题 | 等同一次丢四题，难度自适应与指针机制同时失效 |
| 选项 label 后面加「(Recommended)」 | 那是决策用法。用在题目上＝直接给答案 |
