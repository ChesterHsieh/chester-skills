# LEAPS 策略与候选合约筛选

**输入是两个东西：股票代码 ＋ 预算。** 预算是这次打算花在选择权上的权利金总额，可弹性调整，**全额都用来买选择权**。

用户的核心论点：**长期看好某标的，但资金规模有限，所以用 deep ITM 长天期 call 当槓桿工具**——不是赌方向的彩券，是「融资持股的替代品」。

不要去反推帐户总量、也不要做「单笔不得超过帐户 X%」的检查——资金总量由用户自己在这个 skill 外面管。你只回答一个问题：**这笔预算在这档标的上，买得到什么。**

所有门槛都来自 [references/playbook.md](references/playbook.md)（从用户自己的交易检讨报告萃取）。**先读它**，再往下做。两条分水岭：

1. 赚钱的 call 进场时近 ATM／偏 ITM，赔钱的是深度 OTM
2. **2026-09 新增**：一笔 −$7,010 的部位，方向对（delta 赚 $8,310），却被 IV 崩溃吃掉 $15,248。
   **看对公司不等于买对波动率**——财报窗、IV 百分位、时值占比现在都是硬门槛

> 这个 skill 做筛选与风险计算，**不做投资建议、不下单**。永远不要呼叫 `create_order_instruction`。最后一步是把候选清单交给用户自己决定。

## 流程

### 1. 收输入 ＋ 第 0 关：论述类型（必答，不能跳）

要有**股票代码**和**预算金额**。预算没给就问，别自己假设。

然后**一定要问这一题**（playbook 的第 0 关，问完才往下走）：

> 你的论述能不能写成一句「这家公司会超标」？
> 还是必须写成「这家公司会超标，**而且市场会因此重新定价 50%**」？

- 第一句 = **中位数判断** → 只能用高 delta（≥0.70）。**这是本 skill 的预设路径**
- 第二句 = **尾部判断** → 才轮得到低 delta，但要用户明确写出**触发机制**与**时间窗**

写不出触发机制与时间窗，那就不是尾部论述，退回中位数路径。案例里用户的论述是中位数等级，
工具却是尾部等级（Δ0.47、时值占比 100%）——**这个错配就是亏损的根因**。

标的是美股吗？不是就先提醒 playbook 的系统边界（槓桿 ETP／ETF、时区外市场已暂停，证据是约 −£11k）。用户坚持再继续。

### 2. 抓标的现况（IBKR connector）

```
search_contracts(query="NVDA")
```
选 **symbol 完全相符** 那一列（`NVDA` 而不是 `NVDL`/`NVDU`/`NVDY` 这些槓桿或收益 ETF——它们同样有 OPT section，很容易选错），取其 `underlying_contract_id`。

```
get_price_snapshot(contract_id=<underlying>, market_data_names=[
  "last","bid_ask","implied_vol_underlying","historical_vol",
  "implied_volatility_percentile","misc_statistics"])
```
- `implied-volatility-percentile.high_52w` 是**价格关的 IV 门槛数字**（分数，0.048 = 4.8 百分位 = 很便宜）
- 比对 `implied-vol-underlying.annual_iv` 与 `historical-vol.annual_pct` 判断 IV 相对 HV 贵贱
- **把当前 IV 与 52 週区间一起记下来**：否决时要印给用户看「你付的是什么价」

**财报日一定要查到。**没有财报日 = 第 1 关无法执行，screener 会警告。

### 3. 抓两年日线（重估判读 ＋ 历史频率的分母）

```
get_price_history(contract_id=<underlying>, period=TWO_YEARS, step=ONE_DAY, security_type=STK)
```

这一份负责两件事，不需要外部资料源：

1. **最大单日跳空**（对照财报日）→ 判断上一季是「重估」还是「确认」。
   前一季跳空 > 20% 代表市场**已经**重新定价过，本次大机率只是确认，右尾期望值要下调，
   screener 会自动收紧 delta 下限
2. **滚动 N 交易日报酬的经验分布** → 给交叉点与损益两平一个「历史上多常发生」的对照

日线有 500 根左右，**别整包贴进 JSON**——写成独立档案，用 `price_history_file` 指过去。

### 4. 挑到期日

```
get_option_parameters(underlying_contract_id=<id>)
```
只看 `regular: true` 的月选，挑 **今天起 12–24 个月**的。有 `trading_class` 重复日期时（`NVDA` vs `2NVDA`）选不带前缀的标准链。把 `id` **原样**传下去，别自己拼字串。

### 5. 抓链与逐档报价

```
get_option_data(expiration_id=<verbatim id>, min_strike=..., max_strike=...)
```
range 以 spot 为中心，往下涵盖到 **delta 0.7 左右的履约价**（约 spot 的 0.6–0.9 倍）。

`get_option_data` **只回合约结构，没有价格也没有 greeks**。每个候选履约价要各打一次：

```
get_price_snapshot(contract_id=<call_contract_id>, market_data_names=[
  "bid_ask","implied_vol","option_open_interest","option_volume"])
```

**至少抓两档不同履约价**——交叉点表（C）与等 delta 曝险表（D）都需要成对比较才算得出来。

### 6. 跑 screener（关键步骤）

connector **不回传 delta**，所以自己用 Black-Scholes 算。把上面抓到的东西写成 JSON：

```json
{
  "symbol": "NVDA", "spot": 226.72, "asof": "2026-08-28",
  "budget": 25000, "rate": 0.04, "div_yield": 0.0002,

  "iv_percentile": 0.048,
  "underlying_iv": 0.412,
  "iv_52w": {"low": 0.351, "high": 0.884},

  "earnings_date": "2026-11-19",
  "earnings_confirmed": false,
  "earnings_history": ["2026-08-27", "2026-05-28", "2026-02-26"],

  "thesis_type": "median",
  "tail_trigger": "",
  "tail_window": "",

  "price_history_file": "/tmp/nvda_2y.json",

  "quotes": [
    {"expiry":"20280121","strike":140,"bid":100.90,"ask":103.00,"iv":0.4316,"oi":3893,"volume":0},
    {"expiry":"20280121","strike":165,"bid":80.45,"ask":85.50,"iv":0.4157,"oi":1261,"volume":0},
    {"expiry":"20280121","strike":190,"bid":67.65,"ask":69.50,"iv":0.4064,"oi":8603,"volume":0}
  ]
}
```

| 栏位 | 说明 |
|---|---|
| `iv_percentile` | **一律用分数**（0.048、0.92）。≤1 会被当分数读，>1 当百分位读 |
| `underlying_iv` / `iv_52w` | 否决讯息要印「当前 IV ＋ 52 週区间」，缺了会提醒你补 |
| `earnings_date` | **必填等级**。距财报 ≤5 个交易日 → 硬否决；6–10 个 → 要 `earnings_confirmed: true` |
| `earnings_history` | 配 `price_history` 自动算前次财报跳空；也可直接给 `prior_earnings_move`（0.365）|
| `thesis_type` | `"median"`（预设、严格）或 `"tail"`；tail 必须附 `tail_trigger` 与 `tail_window` |
| `price_history_file` | 两年日线，`[{"date":"2026-09-02","close":338.03}, ...]` 或纯 close 阵列 |
| `target_dollar_delta` | 选填。不给就用「预算全下时最大的那档美元 delta 曝险」当 D 表基准 |

价格一律**每股**（不是每口）。`iv` 取 `implied-vol.annual_iv`。

脚本在本 skill 目录下，`$SKILL` 代表本 skill 的目录（同时支援 `-` 从 stdin 读）：

```bash
python3 $SKILL/screener.py quotes.json
```

产出（上面这份 NVDA 真实报价的实际输出）：

### 7. 交付

分四段讲，不要只丢表：

**① 两关的结论先讲。** 第 0 关（论述类型 ↔ delta 是否匹配）与第 1 关（财报窗、IV 百分位、
时值占比、重估 vs 确认）。有硬否决就直说**「这不是选哪个履约价的问题，是现在不该开这个仓」**，
并附上是哪个数字挡下来的（距财报几个交易日、IV 百分位多少、52 週区间在哪）。

**② 候选清单。** 每档的定位（核心／加速／投机）、通过或否决的原因、这笔预算买几口、
限价起点（中价）、以及各档之间「等效持股 vs 年租金」的取舍。

**③ 两张新表要用嘴巴讲完，不是贴上去就算。**

- **交叉点（C）**：低履约价一路赢，直到股价涨到 X（距 spot +Y%）。
  再给这个门槛的两个机率——**市场定价的 N(d2)** 与**历史频率**——并且**必须讲样本偏误**：
  历史频率来自这两年的样本，若这段期间标的走了大多头，拿它当尾部下注的基准机率就是过度拟合
- **等 delta 曝险（D）**：固定美元 delta 后，深度 ITM 需要的资金更多、但**时值总额少得多**。
  这张表要传达的一句话是：

  > 选深度 ITM 不是「降低槓桿」，是「用同样的槓桿买下更少的波动率曝险」。
  > Delta 和 Vega 是两个独立旋钮，价外把它们焊死在一起。

**④ 论点、催化剂日期与出场规则。** 预定处理日（剩 6–9 个月）、
停利（+100% 卖一半）、认赔（delta<0.15）、
以及**催化剂后窗口**——若进场理由是特定事件（财报／发表会），**事件后 1–2 个交易日内必须做决定**，
因为 IV 崩溃与不确定性解除同时发生，那就是获利窗口的实际宽度。
纯持股替代的部位不套用这条。

## Gotchas（实测踩到的）

- **`option_midpoint_iv` 在长天期合约上回传 `isValid: false`、annualIv 是负数**（实测 NVDA Jan'28 140C 回 `-15.87`）。改用 `implied_vol` 的 `annual_iv`，那个才有效。
- **snapshot 回应的 key 是连字号，不是底线**：请求 `option_open_interest` → 回应是 `option-open-interest`。
- **`iv_percentile` 的单位有歧义**：connector 有时给分数（0.92）有时给百分比（4.8）。screener 的规则是 **≤1 当分数**，所以第 1 百分位要写 `0.01`，写 `1.0` 会被读成第 100 百分位。**一律用分数最安全**，输出会印出它怎么解读的。
- `get_option_data` 不含价格／greeks，得逐档 snapshot——所以 range 要收窄，否则打爆呼叫数。
- **LEAPS 常常整天零成交**（`volume: 0`），流动性要看 **OI 而不是 volume**。实测 Jan'28 165C 的 OI 只有 1261 且半价差 3.0%（$505/口来回成本），190C 的 OI 8603 半价差却只有 1.3%——**OI 高的履约价（整数关卡、100 的倍数）价差明显更好，别只挑 delta 最漂亮的**。
- **预算买不到一口是正常结果**：高价股的 deep ITM LEAPS 单口权利金动辄五位数（$226 的 NVDA，delta 0.90 那口就要 $10,195）。预算不够时脚本会直接否决那档，这时给用户三条路：拉高预算、往 delta 低一点的履约价走（代价是年租金变贵）、或改用 debit spread（A6-4）降低单口成本。
- **口数取整会浪费预算**：单口权利金大时余数很可观（$25k 买 140C 只能买 2 口，剩 $4,610 动不了）。逐档细节里会印出剩余金额——**要主动告诉用户剩多少**，那笔钱可以配到另一档或留着滚动用。
- **所有价外 call 的时值占比都是 100%，一律硬否决**——包含尾部路径想买的那些。尾部论述要买价外，正确工具是 **debit spread（A6-4）**，不是裸 call。
- **交易日是用「扣掉週末」算的，没有假日行事历**。财报窗算出来的天数会略偏多（宁可保守），跨长假时自己再确认一次。
- `search_contracts("NVDA")` 会回一堆 `NVDL`/`NVDU`/`NVDY`/`NVDB` 槓桿与收益 ETF，全都有 OPT section。必须用 symbol 完全相符 + `country_code: US` 筛。
- 报价延迟／盘後会让 `bid_ask` 回空物件；此时 `last.is_close: true`，要跟用户说明这是收盘价不是即时报价。

## 不要做的事

- 不呼叫 `create_order_instruction`、不下单、不改单。
- 不讲「建议买入」这类个人化投资建议；讲的是「这档在框架内／框架外，因为哪个数字」。
- 不为了让某档通过而放宽 screener 门槛。门槛是用户自己的教训换来的——**2026-09 这批门槛的价格是 $7,010**。
- 不拿历史频率当机率讲。它是样本，且样本可能有偏。
