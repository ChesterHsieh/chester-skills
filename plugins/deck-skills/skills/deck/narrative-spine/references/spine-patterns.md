# 四种横轴 · 骨干模式库

「横轴」是把一个复杂主题铺开的那条线。选错轴，后面所有努力都在补救。

一篇只能有一条主轴。四种轴之下可以嵌套次级结构，但主轴不换。

---

## 如何选轴（决策树）

```
读者最想知道的是什么？
│
├─ 「这东西是怎么构成的／难在哪」        → 拆解轴
│
├─ 「为什么会变成现在这样」              → 因果链
│
├─ 「它是怎么走到今天的／接下来去哪」    → 时间轴
│
└─ 「这两条路谁会赢」                    → 对比轴
```

判不出来时的兜底：**问「读者读完最该记住的那句话是什么」**，然后看那句话是关于*构成*、*原因*、*演变*还是*选择*。

---

## 轴型一 · 拆解轴（Teardown）

> 把一个整体拆成部件，逐个检视，再合回来指出真瓶颈。

**适用**：对象是复杂系统——硬件产品、供应链、组织、技术栈、商业模式。

**段落模板**

1. **立整体** — 它是什么，一句话，配一个具体画面
2. **宣告拆法** — 我要按什么维度拆，拆成哪几块（这个宣告本身就是骨干，必须明说）
3. **逐块攻破** — 每块：它负责什么 → 最难的地方 → 现在做到哪 → 谁在做
4. **合回来** — 哪一块是真瓶颈？为什么是它不是别的？
5. **推论** — 瓶颈决定了什么（时间表、赢家、下一步）

**关键动作**：第 2 步的「拆法」必须是有洞见的切法，不是教科书式的标准分类。按标准分类拆 = 复述维基百科；按「哪里最容易断」拆 = 有观点。

**范例**（硅谷101 机器人特刊的做法）：不按「感知/决策/执行」这种标准三分法拆，而是按**「肉身」**拆——把话题限定在物理实现上，再往量产与供应链走。这个切法本身就是论点：软件不是当前瓶颈，身体才是。

**失败模式**
- 拆完各块平均用力，没指出瓶颈 → 变成产品说明书
- 拆法是标准分类 → 没有信息增量
- 第 4 步缺席 → 读者不知道该记住什么

## 轴型二 · 因果链（Causal Chain）

> 现象 → 为什么 → 这又导致 → 所以现在。

**适用**：解释一个反直觉的现状。「为什么 X 明明该发生却没发生」「为什么大家都做错了」。

**段落模板**

1. **摆现象** — 一个具体、可验证、令人意外的事实
2. **排除显而易见的解释** — 「你可能觉得是因为 A，但……」（这步很关键，它建立信任）
3. **逐环推进** — 每一环必须是上一环的**必然**结果，不能跳
4. **抵达根因**
5. **反推** — 根因成立的话，还能推出什么别的（这是给读者的额外回报）

**关键动作**：每一环之间要能通过「所以」测试——把两环之间填上「所以」，读起来必须成立。填不上，就是跳步，要补一环或承认那里是猜测。

**失败模式**
- 跳步：从「芯片贵」直接跳到「所以创业公司做不了」，中间省掉三环
- 单因论：现实往往多因，只讲一因会被内行人拆穿。处理法是明说「这是主因，另外两个次因是……」
- 倒果为因：检核每一环的时间顺序

## 轴型三 · 时间轴（Timeline）

> 起点 → 转折点 → 现在 → 未来的分岔。

**适用**：技术演进、产业变迁、公司兴衰。

**段落模板**

1. **锚定起点** — 不是「很久以前」，是一个具体时刻（谁在哪一年做了什么）
2. **只讲转折点** — 每个节点必须回答「它改变了什么后续走向」
3. **抵达现在** — 现状是前面所有转折的累积结果
4. **分岔** — 未来不给单一预测，给 2–3 条路径 + 各自的前提条件

**关键动作**：**只保留改变了后续走向的节点。** 时间轴最容易堕落成流水账，唯一的解药是对每个节点执行「删掉它，后面的故事还成立吗？」——成立就删。一篇通常只需要 3–5 个节点。

**失败模式**
- 流水账：按年份罗列，每年都提一句
- 后见之明：把历史讲成必然，抹掉当时的不确定性。修正法是保留「当时大家以为会怎样」
- 未来段变成许愿：预测不给前提条件

## 轴型四 · 对比轴（Contrast）

> A 和 B 表面相似 → 关键差异 → 差异的后果 → 谁的赢面大。

**适用**：路线之争、公司对决、新旧方案取舍。

**段落模板**

1. **建立可比性** — 先说清楚为什么值得放在一起比
2. **交错对比** — 按维度组织，每个维度立刻对撞
3. **找出决定性差异** — 多数维度不重要，指出真正决定胜负的那一两个
4. **给出条件式判断** — 「如果 X 成立，A 赢；如果 Y 先发生，B 赢」

**关键动作**：**必须交错，不能分块。** 「先讲完 A 的五点，再讲完 B 的五点」是对比轴最常见的死法——读者读到 B 时已经忘了 A 的对应点。正确做法是按维度走，每个维度里 A、B 立刻碰撞。

**失败模式**
- 分块讲述（见上）
- 假中立：列完差异不给判断。读者要的就是判断，给条件式判断，不要回避
- 维度平均用力：五个维度各占 20%，但其实只有一个维度决定结果

## 混轴警告

中途换轴的代价很高——读者要重新建立方位感。允许的情况只有一种：**主轴之下嵌套次级轴**。

✅ 主轴是拆解轴，其中某个部件的小节内部用时间轴讲它的演进
❌ 前半篇讲历史（时间轴），后半篇讲和对手比（对比轴），两者并列

检核方法：如果两条轴是**并列**关系（可以互换先后），那就是混轴，要拆成两篇或选一条为主。

## 骨架自检四问

写完骨架、开始填内容之前，先过这四题：

1. 主轴能用一句 30 字以内的话说出来吗？
2. 段落标题串起来，读得像一篇摘要吗？
3. 每一段拿掉之后，主轴会断吗？（不断的就是孤儿）
4. 相邻两段能互换顺序吗？（能换 = 并列而非推进）

四题有一题不过，回去改骨架，不要开始填内容。
